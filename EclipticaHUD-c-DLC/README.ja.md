# Ecliptica HUD DLC — ボスの弱点 / 耐性の早見表

[本体プログラム](../README.ja.md) の**独立した小さなアドオン**です。同じ VRChat のログを追い、
**現在どのボスと戦っているか**を判別して、`Weakness&Resistance.txt` の対応する
**弱点 / 耐性**を小さな最前面パネルとして表示します。

> **これは独立したプログラムです。** 本体の `ecliptica-hud-c.exe` を書き換えることも、
> それに依存することもありません。2 つのプログラムは同時に起動でき、それぞれが同じログを
> 読み、互いに影響しません。

## できること

ボス戦で最もよく出る疑問は「今の属性構成で、こいつにダメージは通るのか」。このパネルはその答えを画面の隅に置きます：

```
現在のボス  Beelzebub
物理          1x
火         1.25x  ▲ 弱点
氷         0.75x  ▼ 耐性
電気          1x
光          0.5x  ▼ 耐性
闇          1.5x  ▲ 弱点
毒          0.5x  ▼ 耐性
```

七つの属性はパネル上では**日本語の表示名**で出ます：**物理**（Physical）、**火**（Fire）、
**氷**（Frost）、**電気**（Electric）、**光**（Luminous）、**闇**（Shadow）、**毒**（Poison）。

- **▲ 弱点**（倍率 > 1）は暖色、**▼ 耐性**（倍率 < 1）は寒色、`1x` は中立のグレー
- パネルは最前面・半透明・フォーカスを奪わず、好きな位置へドラッグできます
- ボスが変わればパネルも即座に追随します（切り替わった瞬間、ボス行が一瞬光ります）
- 位置と不透明度は `hr-dlc.ini` に保存され、次回起動時にも引き継がれます

## ビルド

MinGW-w64（または MSVC）が必要です。サードパーティ製の依存はありません。

**MinGW-w64**

```bat
mingw32-make
```

**MSVC**（`x64 Native Tools Command Prompt for VS 2022` 内で）

```bat
build.bat
```

生成物：`hr-dlc.exe`（GUI サブシステム、コンソールウィンドウなし）。

補足：exe のファイル名に `-` が含まれるため、シェルによっては `hr-dlc` とそのまま打つと
引数として解釈されます。`.\hr-dlc.exe` と書くのが最も確実です。

### 多言語版

画面テキストは**簡体中文 / English / 日本語**の 3 種類があり、ソースツリーは 1 つを共用して
ビルド時に言語を選び、3 つの exe を作ります：

```bat
mingw32-make                  :: 中国語（既定）-> hr-dlc.exe
mingw32-make LANG=en          :: 英語          -> hr-dlc-en.exe
mingw32-make LANG=ja          :: 日本語        -> hr-dlc-ja.exe

build.bat                     :: MSVC：中国語
build.bat en                  :: MSVC：英語
build.bat ja                  :: MSVC：日本語
```

補助ツールにも同じ接尾辞が付きます（`test_dlc-en.exe`、`preview_dlc-en.exe` など）。

画面テキストは `uitext_zh.h` / `uitext_en.h` / `uitext_ja.h` にあり、`uitext.h` が
`UI_LANG_EN` / `UI_LANG_JA` に応じて対応するテキストテーブルへ振り分けます。
**文言を追加するときは 3 ファイルすべてに追加する**必要があります。そうしないと、
その言語のビルドが未定義で失敗します。

## 使い方

```bat
hr-dlc.exe                       :: VRChat のログを自動で見つけて追随
hr-dlc.exe --log "D:\...\output_log.txt"   :: 指定したファイルだけを見る
hr-dlc.exe --boss FlyLord        :: ログを読まず、特定のボスを固定表示（デバッグ用）
hr-dlc.exe --demo                :: 内蔵の輪播デモです。ログは不要
hr-dlc.exe --help
```

| 引数 | 説明 |
|---|---|
| （なし） | ログを自動で見つけ、**まず先頭から一度スキャン**して現在のボスを確定してから追随を続ける |
| `--log <ファイル>` | このファイルだけを使う。開けないときは 2 秒ごとに再試行し、自動探索には戻らない |
| `--boss <内部名>` | ログを無視し、この 1 体を固定表示（内部名。例：`FlyLord`、`YukiPhase2`）|
| `--demo` | 代表的なボスを順に輪播し、パネル自体が正常か確認する |
| `--help`、`-h` | ヘルプを表示 |

操作：

| 操作 | 説明 |
|---|---|
| パネルをドラッグ | ウィンドウを移動。位置は自動で記憶される |
| 右上の `✕` をクリック | 閉じる |
| `Ctrl+Alt+W` | グローバル終了（どのウィンドウにフォーカスがあっても有効）|

ログの探索順は本体と同じです：

1. `%USERPROFILE%\AppData\LocalLow\VRChat\VRChat\` の下で最終書き込みが最も新しい `output_log*.txt`
2. 上のディレクトリが見つからないときは `%LOCALAPPDATA%\..\LocalLow\...` に退避
3. さらに exe と同じディレクトリ / カレントディレクトリに退避

VRChat がセッションを切り替えたとき（ディレクトリ内に新しいログファイルが現れたとき）は自動で移ります。

## データファイル形式

データは exe と同じディレクトリの **`Weakness&Resistance.txt`**（UTF-8）から読みます。
ボス 1 体につき 1 段落、段落の区切りは `---` です：

```
Beelzebub
Physical: 1x
Fire: 1.25x
Frost: 0.75x
Electric: 1x
Luminous: 0.5x
Shadow: 1.5x
Poison: 0.5x
---
```

対応する書き方：

| 書き方 | 意味 |
|---|---|
| `Fire: 1.25x` | 具体的な倍率。`>1` は「弱点」、`<1` は「耐性」として表示 |
| `Fire: 1+x (weak)` | 弱点であることだけを示し倍率は無い。パネルは `弱点 ▲` を表示 |
| `Fire: 1-x (resist)` | 耐性であることだけを示し倍率は無い。パネルは `耐性 ▼` を表示 |
| `Others: 0.75x` | 個別に書かれていない残りの属性をまとめてこの倍率にする（例：`Jim C. Bringer(P3)`）|
| 説明文をそのまま書く | 段落に数値表がまったく無いときは、説明文として表示（例：`NaN`、`Jim C. Bringer(P1)`）|

**説明文はデータファイルの元の行ごとに 1 行ずつ表示されます**。ひとつの段落にまとめてから
折り返し直すことはしません。`NaN` の段落はファイル上で 5 文なので、パネル上でも 5 行になります：

```
弱点は現在のモードによって決まります。        <- この行自体が長すぎるため、折り返した続きはインデントされる
  モード。
火モード：弱点は火
氷モード：弱点は氷
電気モード：弱点は電気
闇と光モード：弱点なし
```

**説明文はデータファイルに直接書きます**。表示したい内容をそのまま書けばよく、パネルは翻訳しません。
そのまま表示するだけです（中国語でも英語でもかまいません）。

### 行内コメント

行末に `#` を書くとコメントになり、コメントは表示されません。英語の原文を参考として
横に残しておくのに使えます：

```
NaN
弱点取决于它当前所处的模式。      # The weakness depends on the mode it takes.
火模式：弱点是火                  # Fire mode: weakness is fire
冰模式：弱点是冰                  # Frost mode: weakness is frost
电模式：弱点是电                  # Electric mode: weakness is electric
暗与光模式：没有弱点              # Shadow & Luminous mode: no weakness
---
```

規則：`#` は行頭にあるか、直前に空白がある場合だけコメントになります。`标签#不是注释` のように
文字に密着した `#` は本文の一部です。行全体がコメントの行は読み飛ばされ、パネルに空行を
残しません。

七つの属性キーは `Physical` / `Fire` / `Frost` / `Electric` / `Luminous` / `Shadow` / `Poison` で固定ですが、
大文字小文字は区別しません。**中国語キーや日本語キーを直接書くこともできます**：

| データファイルに書ける | パネル表示 |
|---|---|
| `Physical` / `物` / `物理` | 物理 |
| `Fire` / `火` / `火焰` | 火 |
| `Frost` / `冰` / `冰霜` | 氷 |
| `Electric` / `电` / `雷` | 電気 |
| `Luminous` / `光` / `圣` | 光 |
| `Shadow` / `暗` / `暗影` | 闇 |
| `Poison` / `毒` / `毒素` | 毒 |

つまり、**データファイルには英語キー・中国語キー・日本語キーのどれでも書けます**。
受け付ける別名の集合は 3 言語版で共通で、言語ごとに変わるものではありません。
一方でパネル上の表示名は言語ごとに変わります（中国語版は 物/火/冰/电/光/暗/毒、英語版は
Physical/Fire/…、日本語版は 物理/火/氷/電気/光/闇/毒）。
ボス名（`Beelzebub`、`Jim C. Bringer` など）は固有名詞なので、パネルはデータ表の表記をそのまま使います。

### 説明行の言語プレフィックス

説明行は**言語プレフィックス**に対応しました。これにより数値は共通のまま、1 つのファイルで
3 言語をまかなえます：

```
NaN
zh: 弱点取决于它当前所处的模式。
en: The weakness depends on the mode it takes.
ja: 弱点は現在のモードによって決まります。
```

- プレフィックスは `zh:` / `en:` / `ja:`（小文字）。コロンの後の空白は任意です。
- 各ビルドは自分の言語の行だけを取り込みます。プレフィックスの無い行は 3 言語すべてで表示されます。
- `#` は行頭、または空白の直後にある場合にコメント開始となり、それ以降は無視されます。
  `标签#不是注释` のように文字に密着した `#` は本文の一部です。

**解析規則**（段落を追加するときに知っておくべきこと）：

- コロンの無い行は、**ファイルの先頭・`---` の直後・または現在の段落にすでに数値がある**場合は
  新しいボスの段落名として扱われ、それ以外は現在の段落の説明文になります。
  そのため、段落と段落の間には **`---` を残すことを推奨**します。
- コロンはあるが属性名 / `Others` ではない行（例：`Fire mode: weakness is fire`）は
  一律で説明文として扱われます。
- 段落名がそのまま問い合わせのキーです。形態を持つボスは `名前(P2)` の形で書きます。

### 形態について

ログでは、同じボスの異なる形態は別々のオブジェクト名です。たとえば `Yuki` / `YukiPhase2`、
`JimBringer` / `JimBringerPhase3` です。パネルの問い合わせ規則は次のとおりです：

1. 内部名を表示名へ対応付ける（`FlyLord → Beelzebub`。対応表は `res.c` にあります）
2. `表示名(P形態番号)` を引く（例：`Yuki(P2)`）
3. 見つからなければ形態なしの `表示名` に退避する
4. どちらも見つからなければ → パネルは「データ表にこのボスがありません」を表示

したがって `Yuki(P1)` / `Yuki(P2)` のように形態ごとに分けた項目は正確に一致します。
`Corus` をひとつ書くだけで、そのすべての形態をカバーできます。

`Jim C. Bringer` の三つの形態は表では三とおりの書き方になっており、それぞれがちょうど
一つの型を代表しています：

| 項目 | 内容 | パネルの表示 |
|---|---|---|
| `Jim C. Bringer(P1)` | `No weaknesses and resistances.` | 1 行の説明 |
| `Jim C. Bringer(P2)` | `All damage blocked.` | 1 行の説明 |
| `Jim C. Bringer(P3)` | `Physical: 1x` + `Others: 0.75x` | 数値表 + Others |

ある形態が表に本当に無い場合（例：新しいボスがまだ補われていない）、パネルは正直に
「データ表にこのボスがありません」と表示し、どこに補うべきかを示します。

## 仕組み

```
VRChat output_log.txt
        │  logtail.c   位置特定 + 先頭から走査 + 追随
        ▼
   現在のボス（内部名 + 形態番号）
        │  res.c       表示名の対応付け -> 表引き
        ▼
   弱点 / 耐性 の項目
        │  dlcui.c     版式計算 + GDI 二重バッファ描画
        ▼
   最前面のレイヤードウィンドウ（dlc.c）
```

- **見るのは三つだけ**：`now fighting boss:` の開戦行、`Boss X dead` の撃破行、
  そして `now in intermission` / `now in lobby` / `now in stage:` / 部屋への出入りといった
  「この 1 戦は終わった」という合図です。本体プログラムは完全な解析を行いますが、
  ここでは意図的に最小限にとどめており、両者は互いに影響しません。
- ログは**先頭から一度スキャン**してから追随します。HUD は戦闘の途中で起動されることが多く、
  追加された行だけを見ても現在のボスが分からないためです。走査するのは普通のテキスト行なので、
  数 MB のログでも数十ミリ秒で済みます。
- 版式（タイトル行 / ボス行 / 属性表 / ステータスバー）は `dlcui_layout()` が一度に算出し、
  **描画とヒットテストが同じ矩形を共用**するため、「ボタンが押せない」ことは起きません。
- ウィンドウは `WS_EX_LAYERED | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` で、
  VRChat のフォーカスを奪いません。DPI 対応で、60%〜200% の拡大縮小でも版式は一定です。

## テストと検証

```bat
mingw32-make test        :: ロジックテスト（127 項のチェック）
mingw32-make preview     :: パネルのプレビュー画像をオフスクリーン描画。ディスプレイ不要
```

`test_dlc.c` がカバーする範囲：データ表の解析（数値 / 記号 / `Others` / 説明型）、
ボス表示名の対応付け（18 件）、基礎名と形態番号の抽出、そして各種の「見つからない」ときの戻り値。

`preview_dlc.exe` はディスプレイの無い環境でも任意の状態をレンダリングでき、レイアウトの
確認に便利です：

```bat
preview_dlc.exe "Weakness&Resistance.txt" FlyLord 1 100 out.bmp
preview_dlc.exe "Weakness&Resistance.txt" -       1 100 waiting.bmp   :: ボス戦なし
preview_dlc.exe "Weakness&Resistance.txt" YukiPhase2 2 100 yuki2.bmp
```

実測でカバーした状態：

![八つの状態](dlc_states.png)

|  | 左 | 中 | 右 |
|---|---|---|---|
| **上** | 通常の数値段落（ベルゼブブ）| 複数行の説明（NaN）| 1 行の説明（Jim P1）|
| **中** | 1 行の説明（Jim P2）| `Others:` の段落（Jim P3）| 記号での書き方（Yuki P2）|
| **下** | ボス戦なし | 表に無いボス | （空）|

| 状態 | 結果 |
|---|---|
| 通常の数値段落（ベルゼブブ）| 7 属性 + 弱点/耐性のマーク + 配色が正しい |
| `Others:` の段落（Jim P3）| 物理 1x、残りは Others により 0.75x ▼耐性 |
| 記号の段落（Yuki P2）| 火 は「弱点 ▲」、氷/電気 は「耐性 ▼」を表示 |
| 複数行の説明（NaN）| **データファイルの元の行ごとに 1 行ずつ表示**。折り返すのは幅を超えた行だけ |
| 1 行の説明（Jim P1 / P2）| 原文の 1 行がそのまま 1 行 |
| ボス戦なし | 「現在のボス —」「ボス戦を待っています…」を表示 |
| 表に無いボス | 「データ表にこのボスがありません」を表示 |

パネル上の文字は **ボス名**（固有名詞。データ表の表記をそのまま使う）を除き、
すべて日本語です：タイトル、ステータスバー、七つの属性名、そしてデータファイルに書かれた説明文。

`test_dlc-ja.exe --log <ログ>` を使うと、ウィンドウを開かずに「実際のログからボスを認識する」
という経路を検証できます。どのボスを認識したか、見つかった項目、各属性の判定を出力します。
**出力はビルドした言語に従います**（日本語版なら日本語のラベル）：

```
===== QueenBug の開戦を捕捉した後 =====
ログファイル : cut.log
交戦中のボス : QueenBug
表示名       : Vesra
形態         : 1
検索キー     : Vesra(P1)  /  Vesra
該当項目     : Vesra
  物理 Physical    1.00x   -
  火 Fire           1.50x   弱点
  ...
```

中国語版と日本語版では、各行に**パネル表示名とデータファイルのキーを並べて**出します
（例：`物 Physical  1.50x  弱`）。表に何を書けばよいか一目で分かります。
英語版では両者が同じ綴りなので 1 回だけ表示します。

実際のログで検証した例：

| ログ上のボス | 表示名 | 結果 |
|---|---|---|
| `Pandora` | Pandora | 7 項の数値。火 1.5 弱点 / 氷 0.3 耐性 … |
| `QueenBug` | Vesra | 名前の対応付けが働き、Vesra の段落を取得 |
| `ConeHeadPhase2` | Cone Head | まず `Cone Head(P2)` を試して外れ → `Cone Head` に退避 |
| `Nan` | NaN | 説明型。7 項は `—` + 説明文を表示 |

## 既知の制限

- **Windows** のみ対応です（Win32 + GDI）。
- 耐性データは**完全にこの txt ファイル由来**です。ゲーム自体はこれらの数値を出力しないため、
  データが正しいかどうかは、このファイルを保守しているかどうかにかかっています。
  パネルは「表を引いて表示する」だけです。
- インターフェースの文字はビルドした言語に従います（3 言語版とも、属性名・タイトル・
  ステータスバー・説明文がそれぞれの言語になります）。データファイル側のキーは
  英語 / 中国語 / 日本語のどれでも受け付けます。ボス名（Beelzebub、Jim C. Bringer など）は
  固有名詞なので、3 言語版ともデータ表の綴りのままです。
- データファイルの形式解析は**約束ごとに基づきます**：段落の間には `---` を残すことを推奨し、
  七つの属性名は上記の綴りに従ってください。書き間違えてもクラッシュはしませんが、
  「このボスがいません」と表示されたり、1 行欠けたりします。
- 一度に表示するボスは 1 体だけです。ワールド内に複数のボスが同時に存在する場合、
  パネルはログの最後の `now fighting boss` のボスを表示します。
